## What shipped

1. **Arms slot.** `Inventory.EQUIP_SLOTS` gains `&"arms"`. `slot_for()` maps `armor_arms`/`gloves` to arms, and the specific slots now come before the generic `armor`/`clothing` fallbacks (before this, `travel_sleeves`/`travel_trousers`, which are tagged `clothing` too, would have gone to body). `equipped_armor()` and `equipped_health_bonus()` count arms. `has_raid_protection()` is unchanged. Inventory UI: an "Arms" label; the desktop equipment grid is now 4 wide (head/body/arms/legs, weapon/tool/ring/ring, food/food) because a fourth row of 3 cut Food 2 off at 1600x900. Phone stays 3 wide. Old saves load with arms empty.
2. **Visual equipment.** `scripts/player/player_equipment.gd` (`PlayerEquipment`, a child of Player, set up after `rig.setup`). It hides the single survivor mesh, attaches `body/body_{helmet,chest,arms,legs}.glb`, and on every `inventory.changed` it equips or unequips the difference per slot from the item's new `visual` field (`ItemDef.visual`, e.g. `"forager/helmet"`). A body region is hidden only while an attached piece's kit.json `hides` lists it, so travel_clothes with no helmet leaves the head showing. If the body GLBs are missing it keeps the single mesh. The shared skinned-attach code is `RiggedModel.attach_skinned()` (static), used by both armor and saddle. Attached meshes get the same web-safe material as the base mesh (`Player.web_safe_mesh`, pulled out of `_make_survivor_web_safe`).
3. **Items + recipes.** The 11 items from the spec in `data/items.json` with `visual`, recipes in `data/recipes.json` (tailoring, workbench): travel at level 1 (cloth + fibre), forager at min_level 10 (cloth, fibre, hide), hide and bone at min_level 30 (hide, bone, lashing). Chest/legs cost double. Icon aliases in `icons_manifest.json` reuse the hide icons. **ASSUMPTION:** all stats, tiers and costs are the art spec's suggestion or my own; the PRD doesn't specify these sets. Travel clothes are craftable, not a starting outfit; the new-game start inventory is unchanged.
4. **Mount.** `CreatureView.begin_ride()` reads `assets/creatures/<id>/mount/mount.json` when present: it attaches the saddle skinned to the mount skeleton and computes the socket offset once from `rider_in_mount` (model space, not `rider_offset`) against the Spine2 rest pose at live scale. `rider_transform()` gives the rider root each frame. `Player.mount()`: for a saddled mount the CharacterBody reparents to the creature root (physics off the bone, with collision exceptions both ways), and `_follow_saddle` runs on the mount's `Skeleton3D.skeleton_updated`. It sets `rig.global_transform = rider_transform() * inverse(mesh_root yaw)`, which cancels RiggedModel's +Z facing turn and drops the 1.18 lift (rig global scale reads 1.000 while mounted). Dismount disconnects, frees the saddle and restores the rig's local transform. Mounts with no mount.json keep the old hips-socket path.
5. **attack_primary speed.** The base factor went from 1.5 to 1.0. The weapon-rate fit (`duration * rate / 0.65`) still sets the real speed (about 1.86x at rate 1.0). Damage is still applied on the swing in `hunt.gd`; I did not sync it to the clip (if you do, survivor contact is about 30%). `anim_events.json` is untouched.

New lab: `--lab=equip_mount_lab` (scene `scenes/dev/equip_mount_lab.tscn`). It asserts the slot mapping, body-region visibility for each kit, mixed and unequip, armor/HP totals with arms, the saddle path, rider height on the howdah, the dropped 1.18, mount_idle, and that dismount restores the rig. Run it with a display to get screenshots at `/tmp/dfs-equip-*.png`.
